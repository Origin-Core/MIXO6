# راه‌اندازی MIXO6 با Supabase (راهنمای فارسی)

این نسخه برای Auth و دیتابیس به سرور Node.js جداگانه نیاز ندارد. Supabase سرویس حساب کاربری و PostgreSQL را میزبانی می‌کند و برنامه‌ی Windows از HTTPS به Auth API و PostgREST وصل می‌شود.

## 0) قبل از صرف وقت، دسترسی بدون VPN را آزمایش کن

Supabase دیتاسنتر ایران ندارد و دسترسی از همه‌ی ISPها/رنج‌های IP ایران تضمین‌شده نیست. شرایط رسمی Supabase نیز از محدودیت‌های کنترل صادرات نام می‌برد؛ پیش از استفاده‌ی واقعی از حساب و نگهداری داده‌ی کاربران، مطمئن شو استفاده‌ی موردنظر با شرایط سرویس و قوانین قابل‌اجرا سازگار است: https://supabase.com/terms از همان اینترنتی که بیشتر کاربران MIXO6 دارند، ابتدا این کارها را انجام بده:

1. باز کن: https://supabase.com/dashboard
2. اگر Dashboard باز شد، یک پروژه‌ی آزمایشی بساز و API URL آن را دریافت کن.
3. بعد از ساخته‌شدن پروژه، PowerShell را باز کن و جایگزین `<PROJECT_REF>` کن:

```powershell
$hostName = "<PROJECT_REF>.supabase.co"
Resolve-DnsName $hostName
Test-NetConnection $hostName -Port 443
```

`TcpTestSucceeded : True` فقط ارتباط TCP را تأیید می‌کند؛ تست نهایی را از داخل MIXO6 با دکمه‌ی «ذخیره و تست اتصال Supabase» انجام بده. اگر Dashboard یا API بدون VPN در شبکه‌ی ایران باز نمی‌شود، Supabase شرط «بدون VPN برای همه‌ی کاربران ایران» را برآورده نکرده؛ در این حالت قبل از انتشار عمومی باید سرویس قابل‌دسترسی داخل ایران انتخاب شود. از هیچ روش دورزدن محدودیت در این راهنما استفاده نشده است.

## 1) ایجاد پروژه

1. در https://supabase.com/dashboard وارد شو و `New project` را بزن.
2. نام: `MIXO6`.
3. یک رمز قوی برای Database Password بساز و در Password Manager خودت ذخیره کن. این رمز با کلید عمومی برنامه فرق دارد.
4. برای تست اولیه `Central EU (Frankfurt)` را امتحان کن؛ اگر نتیجه‌ی پینگ/دسترسی مناسب نبود، `Mumbai` یا `Singapore` را در یک پروژه‌ی آزمایشی جداگانه با اتصال واقعی مقایسه کن. نزدیک‌بودن جغرافیایی تضمین دسترسی بدون VPN نیست.
5. پلن Free را انتخاب کن و ساخت پروژه را تمام کن.

صفحه‌های رسمی: https://supabase.com/pricing/ و https://supabase.com/docs/guides/platform/regions

## 2) اجرای SQL دیتابیس

1. پروژه را باز کن → `SQL Editor` → `New query`.
2. فایل `supabase/migrations/20261027000000_mixo6.sql` را از ZIP با ویرایشگر متن باز کن.
3. تمام SQL را کپی کن، در SQL Editor قرار بده و `Run` را بزن.
4. باید query بدون خطا تمام شود. در `Table Editor` باید جدول‌های `profiles`، `lobbies` و `lobby_members` و view به نام `lobby_cards` را ببینی.

SQL شامل RLS، سیاست‌های دسترسی و توابع امن برای ساخت/پیوستن/بستن لابی است. آدرس سرور بازی در view عمومی `lobby_cards` وجود ندارد؛ آدرس فقط از تابع `mixo6_join_lobby` و پس از احراز هویت/عضویت برمی‌گردد. رمز عبور کاربران را خود Supabase Auth مدیریت می‌کند؛ ما هیچ ستون رمز عبور در جدول عمومی نداریم.

## 3) تنظیم ایمیل و تأیید حساب

1. در پروژه برو به `Authentication` → `Sign In / Providers` (ممکن است نام بخش در نسخه‌ی داشبورد متفاوت باشد) → `Email`.
2. Email provider را فعال نگه دار و `Confirm email` را روشن کن.
3. **ارسال پیش‌فرض Supabase برای محصول عمومی کافی نیست**: فقط به ایمیل‌های مجاز اعضای تیم پروژه می‌فرستد و حد پیش‌فرض آن بسیار پایین (۲ ایمیل در ساعت) است. برای ثبت‌نام کاربران واقعی باید SMTP اختصاصی تنظیم شود. راهنمای دقیق، شامل فیلدهای پنل و SMTP نمونه در [`SMTP.fa.md`](SMTP.fa.md) است. مستندات: https://supabase.com/docs/guides/auth/auth-smtp
4. برو به `Authentication` → `Emails` → `SMTP Settings` و اطلاعات SMTP یک سرویس ایمیل تراکنشی را که برای استفاده‌ات مجاز و از سمت Supabase قابل اتصال است وارد کن. برای شروع بدون دامنه، Gmail SMTP را طبق `SMTP.fa.md` امتحان کن؛ برای سرویس عمومی کم‌محدودیت‌تر، Brevo پلن رایگان بدون تاریخ انقضا با ۳۰۰ ایمیل روزانه دارد اما دامنهٔ خودت و SPF/DKIM معتبر لازم دارد. هیچ رمز SMTP را در اپ دسکتاپ یا GitHub نگذار.
5. چون UI فعلی کد تأیید را می‌گیرد، در `Authentication` → `Email Templates` → `Confirm signup` قالب را طوری تنظیم کن که کد OTP درج‌شده با `{{ .Token }}` برای کاربر ارسال شود (مثلاً «کد تأیید MIXO6 شما: {{ .Token }}»). برای پروژه‌های جدید Free، سفارشی‌کردن قالب ایمیل پیش‌فرض بدون SMTP اختصاصی ممکن است محدود باشد؛ مستند تغییرات را ببین: https://supabase.com/changelog/46599-changes-to-email-template-customisation-on-free-tier
6. قالب را ذخیره کن و یک ثبت‌نام آزمایشی با ایمیلی که به آن دسترسی داری انجام بده. کد را در MIXO6 وارد کن. پیام ایمیل ممکن است در Spam هم باشد.

SMTP به سورس یا EXE وارد نمی‌شود. راهنمای دقیق فیلدها برای شروع با Gmail و گزینه‌ی دامنه‌محور در [`SMTP.fa.md`](SMTP.fa.md) آمده است. از رمز اصلی Gmail استفاده نکن؛ App Password بساز و فقط در پنل Supabase بگذار. وضعیت دسترسی و مجازبودن هر سرویس را با شرایط خودش بررسی کن.

## 4) کلیدهای اتصال (مهم)

Project URL و Publishable key عمومی‌ای که برای MIXO6 تعیین شده‌اند داخل سورس به عنوان مقادیر عمومی کلاینت قرار گرفته‌اند. Publishable key برای کلاینت طراحی شده؛ کلید Secret نیست.

در `Project Settings` → `API Keys` (یا `Data API` / `API`) این دو مورد را پیدا کن:

- **Project URL**: شکل معمول `https://<PROJECT_REF>.supabase.co`
- **Publishable key** که معمولاً با `sb_publishable_` شروع می‌شود؛ در پروژه‌های قدیمی‌تر می‌توان از کلید عمومی `anon` استفاده کرد.

در نسخه‌ی جدید MIXO6، Project URL و Publishable key عمومی از قبل تنظیم شده‌اند. وارد تنظیمات برنامه شو و `ذخیره و تست اتصال Supabase` را بزن. اگر پروژه را عوض کرده‌ای، URL ریشه را فقط تا `.co` و کلید عمومی را وارد کن؛ `/rest/v1`، `/auth/v1` یا `/api` اضافه نکن.

### کلیدهایی که نباید در برنامه باشند

- هرگز `service_role`، `sb_secret_...`، رمز دیتابیس، رمز SMTP یا Access Token مدیریت Supabase را در MIXO6، مخزن GitHub یا اسکرین‌شات عمومی قرار نده.
- Publishable/anon key به‌تنهایی راز نیست و می‌تواند در کلاینت باشد، **اما فقط همراه RLS درست**؛ SQL این مخزن برای همین منظور سیاست‌های دسترسی تعریف می‌کند.
- اگر به‌اشتباه کلید secret را وارد کردی، آن را در تنظیمات برنامه ذخیره نکن؛ در صورت افشای عمومی آن را در Dashboard چرخش/تعویض کن.

برای ورود با نام کاربری علاوه بر SQL، باید Edge Function طبق [`FUNCTIONS.fa.md`](FUNCTIONS.fa.md) deploy شود؛ ورود با ایمیل مستقیم از Supabase Auth استفاده می‌کند.

## 5) محدودیت‌ها و رفتار پلن رایگان

سهمیه‌های رسمی فعلی Free شامل ۵۰۰MB دیتابیس برای هر پروژه، ۵۰٬۰۰۰ کاربر فعال ماهانه، ۵GB ترافیک خروجی و ۱GB ذخیره‌سازی فایل است. پروژه‌ی کم‌فعالیت ممکن است بعد از ۷ روز غیرفعال‌بودن pause شود. برای پلن رایگان بک‌آپ قابل دانلود دیتابیس فراهم نیست؛ SQL را در مخزن نگه دار و از داده‌های لازم مرتب export بگیر. جزئیات رسمی: https://supabase.com/docs/guides/platform/billing-on-supabase و https://supabase.com/docs/guides/platform/free-project-pausing

این پلن برای نمونه‌ی اولیه است، نه ضمانت میزبانی دائمی بدون محدودیت. اگر اطلاعات کاربران واقعی نگهداری می‌شود، سیاست حریم خصوصی و روند پشتیبان‌گیری نیز لازم است.

## 6) انتشار برنامه

1. این پروژه را به مخزن خصوصی/عمومی GitHub خودت push کن.
2. از `Actions` مطمئن شو Windows release workflow دسترسی نوشتن Release را دارد.
3. Tag انتشار را ایجاد و push کن؛ فایل Windows x64 به‌صورت GitHub Release ساخته می‌شود.
4. Project URL و Publishable key عمومی همین پروژه در تنظیمات پیش‌فرض نسخه هستند؛ نیازی به واردکردن آن‌ها در GitHub Secrets نیست. هیچ کلید Secretی نباید در CI، سورس یا EXE قرار بگیرد.
